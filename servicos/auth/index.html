    Auth

    Responsável: Nicolas · Repositórios: pna26/auth (interface) e pna26/auth-service (implementação)

    O Auth cuida da identidade do usuário. Ele:

    1. cadastra (POST /auth/register), repassando ao Account;
    2. faz o login (POST /auth/login): pede ao Account para conferir e-mail e senha e, se der certo, gera um JWT e o devolve no cookie __store_jwt_token;
    3. resolve o token para o gateway (POST /auth/solve): confere a assinatura e a validade e devolve o id da conta;
    4. devolve os dados de quem está logado (GET /auth/me) e faz o logout (apaga o cookie).

    O Auth não tem banco: quem guarda as contas e os hashes das senhas é o Account. É um serviço Spring Boot (Web MVC) + OpenFeign, com o JWT feito pela biblioteca JJWT 0.13. Segue o hands-on 3 do curso.

    Dois repositórios: interface e implementação

    Repositório Conteúdo Quem usa
    auth AuthController (interface com as rotas e o nome do cookie) e os DTOs RegisterIn, LoginIn e TokenOut o auth-service (implementa)
    auth-service AuthResource, AuthService, JwtService, Dockerfile e k8s/ vira a imagem auth-service

    O auth-service também depende da interface do Account (store:account:1.0.0) e a usa como cliente Feign (@EnableFeignClients(basePackages = "store.account")): chamar o Account é chamar um método Java, e o Feign transforma isso em POST http://account:8080/accounts/login.

    Rotas

    Método Rota Entrada Saída Token no gateway?
    POST /auth/register { name, email, password } 200 não
    POST /auth/login { email, password } 200 + Set-Cookie: __store_jwt_token=<jwt> ou 401 não
    GET /auth/logout — 200 + cookie vazio com Max-Age=0 não
    GET /auth/me header id-account (posto pelo gateway) { id, name, email } sim
    POST /auth/solve { token } { idAccount } ou 401 só o gateway chama, por dentro
    GET /auth/health-check — 200 sim

    Login e uso do token

    sequenceDiagram
    actor U as Usuário
    participant G as gateway
    participant A as auth
    participant C as account
    U->>G: POST /auth/login {email, password}
    G->>A: (rota aberta)
    A->>C: POST /accounts/login (Feign)
    C-->>A: {id, name, email} ou 401
    A->>A: JWT assinado (HMAC-SHA256)
    A-->>U: 200 Set-Cookie: __store_jwt_token
    U->>G: GET /accounts (cookie)
    G->>A: POST /auth/solve {token}
    A->>A: confere assinatura, nbf e exp
    A-->>G: {idAccount}
    G->>C: GET /accounts + id-account

    O gateway guarda o resultado do /auth/solve no Redis por alguns minutos (ver Cache); assim o Auth não é chamado em toda requisição.

    JWT

    Campo Valor
    jti (id) id da conta: é o que o /auth/solve devolve
    sub nome da conta
    email e-mail da conta
    iss Insper::PMA
    nbf / exp agora / agora + JWT_DURATION
    Assinatura HMAC-SHA256 com a chave JWT_SECRET_KEY (base64 de 32 bytes)

    O token não leva senha e não é criptografado (qualquer um decodifica o conteúdo em base64); o que impede a falsificação é a assinatura. Qualquer alteração no token, ou um token assinado com outra chave, faz o parseSignedClaims falhar e o /auth/solve responder 401. O mesmo vale para um token vencido.

    Cookie

    Atributo Por quê
    HttpOnly JavaScript da página não lê o cookie, então um XSS não consegue roubar o token
    Secure o navegador só manda o cookie por HTTPS (ou para localhost)
    SameSite=None permite que um front-end em outra origem chame a API com o cookie (exige Secure)
    Path=/, Max-Age = duração do token o cookie vale para todas as rotas e some junto com o token

    O Secure é o motivo de o navegador não guardar o cookie no EKS, que hoje atende só por HTTP: ver HTTPS (limitação conhecida).

    Decisões

    Decisão Motivo
    Auth sem banco, conferindo a senha no Account Um só dono dos dados das contas. O Auth nunca vê o hash: manda a senha ao Account e recebe só { id, name, email }.
    JWT stateless Para validar não precisa consultar banco, só a chave. Qualquer réplica do Auth valida qualquer token.
    Login errado → 401 O AuthService converte o 401/400 do Account (que chega como FeignException) em 401 Invalid credentials.
    Token inválido → 401, sem stack trace O JwtService captura a JwtException e responde 401; o gateway trata 4xx do solve como "não autenticado".
    JWT_SECRET_KEY obrigatória Não existe chave padrão no código: sem a variável, o Auth não sobe. Uma chave no repositório público deixaria qualquer pessoa gerar tokens válidos. No compose ela vem do .env (o scripts/build.sh gera uma aleatória); no EKS, do Secret auth-secrets.
    JJWT com versão fixa (0.13.0) A API do JJWT mudou bastante entre versões (parserBuilder → parser().verifyWith); com a versão fixa o build não quebra sozinho.

    Limitações

    Limitação Como ficaria em produção
    Erro do Account no cadastro (ex.: e-mail duplicado, senha curta) chega ao usuário como 500 tratar a FeignException no create e repassar o status do Account (400, 409)
    GET /auth/me com um id que não existe mais (conta apagada, token ainda válido) devolve 500 repassar o 404 do Account
    Logout só apaga o cookie: o token continua válido até o exp se alguém tiver uma cópia lista de tokens revogados (por jti) no Redis, consultada pelo gateway
    Sem papéis (todo usuário logado pode tudo) um claim de papel no JWT (por exemplo role: admin) e a checagem no gateway

    package store.auth;

import java.util.Map;

import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestHeader;

import store.account.AccountOut;

@FeignClient(
    name="auth",
    url="http://auth:8080"
)
public interface AuthController {

    public static final String AUTH_COOKIE_TOKEN = "__store_jwt_token";

    @PostMapping("/auth/register")
    public ResponseEntity<Void> create(
        @RequestBody RegisterIn in
    );

    @PostMapping("/auth/login")
    public ResponseEntity<Void> login(
        @RequestBody LoginIn in
    );

    @GetMapping("/auth/me")
    public ResponseEntity<AccountOut> me(
        @RequestHeader(value = "id-account", required = true) String idAccount
    );

    @PostMapping("/auth/solve")
    public ResponseEntity<Map<String, String>> solveToken(
        @RequestBody TokenOut map
    );

    @GetMapping("/auth/logout")
    public ResponseEntity<Void> logout();

    @GetMapping("/auth/health-check")
    public ResponseEntity<Void> healthCheck();

}

    package store.auth;

import java.time.Duration;
import java.util.Map;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.HttpHeaders;
import org.springframework.http.ResponseCookie;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.RestController;

import store.account.AccountOut;

@RestController
public class AuthResource implements AuthController {

    @Autowired
    private AuthService authService;

    @Override
    public ResponseEntity<Void> create(RegisterIn in) {
        final Register register = AuthParser.to(in);
        authService.create(register);
        return ResponseEntity.ok().build();
    }

    @Override
    public ResponseEntity<Void> login(LoginIn in) {
        final String token = authService.login(in.email(), in.password());
        return ResponseEntity
            .ok()
            .header(
                HttpHeaders.SET_COOKIE,
                buildTokenCookie(AuthController.AUTH_COOKIE_TOKEN, token, authService.getDuration()).toString()
            )
            .build();
    }

    @Override
    public ResponseEntity<AccountOut> me(String idAccount) {
        return ResponseEntity.ok(authService.me(idAccount));
    }

    @Override
    public ResponseEntity<Void> logout() {
        return ResponseEntity
            .ok()
            .header(
                HttpHeaders.SET_COOKIE,
                buildTokenCookie(
                    AuthController.AUTH_COOKIE_TOKEN,
                    null,
                    0l
                ).toString()
            )
            .build();
    }

    @Override
    public ResponseEntity<Void> healthCheck() {
        return ResponseEntity.ok().build();
    }

    @Override
    public ResponseEntity<Map<String, String>> solveToken(TokenOut map) {
        return ResponseEntity.ok(authService.solve(map.token()));
    }

    private ResponseCookie buildTokenCookie(String alias, String content, Long duration) {
        return ResponseCookie.from(alias, content)
            .httpOnly(authService.getHttpOnly())
            .sameSite("None")
            .secure(true)
            .path("/")
            .maxAge(Duration.ofMillis(duration))
            .build();
    }

}

    package store.auth;

import java.util.Map;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

import feign.FeignException;
import store.account.AccountController;
import store.account.AccountIn;
import store.account.AccountOut;

@Service
public class AuthService {

    @Autowired
    private AccountController accountController;

    @Autowired
    private JwtService jwtService;

    @Value("${store.jwt.duration}")
    private Long duration;

    @Value("${store.jwt.httpOnly}")
    private Boolean httpOnly;

    public void create(Register register) {

        accountController.create(
            AccountIn.builder()
                .name(register.name())
                .email(register.email())
                .password(register.password())
                .build()
        );

    }

    public String login(String email, String password) {
        final AccountOut account;
        try {
            // o account calcula o hash da senha e compara com o hash guardado
            account = accountController.login(
                AccountIn.builder().email(email).password(password).build()
            ).getBody();
        } catch (FeignException.Unauthorized | FeignException.BadRequest e) {
            throw new ResponseStatusException(
                HttpStatus.UNAUTHORIZED, "Invalid credentials"
            );
        }
        return jwtService.generate(account, getDuration());
    }

    public long getDuration() {
        return duration;
    }

    public boolean getHttpOnly() {
        return httpOnly;
    }

    public Map<String, String> solve(final String jwt) {
        return Map.of(
            "idAccount", jwtService.getId(jwt)
        );
    }

    public AccountOut me(String idAccount) {
        return accountController.findById(idAccount).getBody();
    }

}

    package store.auth;

import java.util.Base64;
import java.util.Date;
import java.util.Map;

import javax.crypto.SecretKey;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.JwtParser;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import store.account.AccountOut;

@Service
public class JwtService {

    @Value("${store.jwt.secretKey}")
    private String secretKey;

    public String generate(AccountOut account, long duration) {

        Date now = new Date();
        return Jwts.builder()
            .header().and()
            .id(account.id())
            .issuer("Insper::PMA")
            .claims(Map.of("email", account.email()))
            .signWith(getKey())
            .subject(account.name())
            .notBefore(now)
            .expiration(new Date(now.getTime() + duration))
            .compact();
    }

    private SecretKey getKey() {
        return Keys.hmacShaKeyFor(Base64.getDecoder().decode(secretKey));
    }

    public String getId(String jwt) {
        try {
            JwtParser parser = Jwts.parser().verifyWith(getKey()).build();
            // confere a assinatura, o nbf e o exp: senão, JwtException
            Claims claims = parser.parseSignedClaims(jwt).getPayload();
            return claims.getId();
        } catch (JwtException e) {
            throw new ResponseStatusException(
                HttpStatus.UNAUTHORIZED, "Invalid token");
        }
    }

}

    # Auth no EKS: só é acessível pelo gateway (ClusterIP), como no compose.
# Chama o account em http://account:8080 (nome do Service do account).
# O CI troca a imagem ":latest" pela tag do commit antes do kubectl apply.
#
# O Secret com a chave do JWT NÃO fica no Git. Crie uma vez por cluster:
#   kubectl create secret generic auth-secrets -n store \
#     --from-literal=JWT_SECRET_KEY=<chave base64 de 32 bytes>
apiVersion: v1
kind: ConfigMap
metadata:
  name: auth-configmap
data:
  JWT_HTTP_ONLY: "true"
  JWT_DURATION: "3600000"
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: auth
  labels:
    app: auth
spec:
  replicas: 1
  selector:
    matchLabels:
      app: auth
  template:
    metadata:
      labels:
        app: auth
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1001
        runAsGroup: 1001
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: auth
          image: 637423273088.dkr.ecr.us-east-2.amazonaws.com/auth-service:latest
          # o CI sempre aplica uma tag nova (sha-xxxxxxx), então não precisa de Always
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: auth-configmap
            - secretRef:
                name: auth-secrets
          readinessProbe:
            tcpSocket:
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 5
          livenessProbe:
            tcpSocket:
              port: 8080
            initialDelaySeconds: 60
            periodSeconds: 10
          resources:
            requests:
              memory: "256Mi"
              cpu: "100m"
            limits:
              memory: "512Mi"
              cpu: "1"
          securityContext:
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true
            capabilities:
              drop: [ "ALL" ]
          volumeMounts:
            - name: tmp
              mountPath: /tmp
      volumes:
        - name: tmp
          emptyDir: {}
---

  name: auth

    Configuração

    Variável Padrão no código Compose EKS Uso
    JWT_SECRET_KEY — (obrigatória) .env Secret auth-secrets chave HMAC do JWT, base64 de 32 bytes (openssl rand -base64 32)
    JWT_DURATION 3600000 (1 h) 86400000 (24 h) 3600000 (1 h) validade do token e do cookie, em milissegundos
    JWT_HTTP_ONLY true true true atributo HttpOnly do cookie

    Como testar

    Pelo gateway (compose em http://localhost):

    curl -s -X POST localhost/auth/register -H "Content-Type: application/json" \
  -d '{"name":"Ana","email":"ana@insper.edu.br","password":"segredo123"}'

curl -si -X POST localhost/auth/login -H "Content-Type: application/json" \
  -d '{"email":"ana@insper.edu.br","password":"segredo123"}' | grep -i set-cookie
# set-cookie: __store_jwt_token=eyJ...; Path=/; Max-Age=86400; ...; Secure; HttpOnly; SameSite=None

curl -s localhost/auth/me -H "Cookie: __store_jwt_token=eyJ..."
# {"id":"...","name":"Ana","email":"ana@insper.edu.br"}

    Um token alterado (troque uma letra do meio) faz o /auth/me responder 401, porque a assinatura deixa de bater. O scripts/smoke-test.sh repete esse roteiro contra o compose ou o ELB do EKS.
