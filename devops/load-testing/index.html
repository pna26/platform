    Testes de carga

    Responsável: Gabriel

    Ferramenta: k6 (Grafana Labs), rodando em container — ninguém do grupo precisa instalar nada além do Docker. Escolhemos o k6 em vez do JMeter/Locust porque o teste é um arquivo JavaScript versionado no repositório, os limites de aceitação (thresholds) ficam no próprio script e ele envia as métricas direto para o Prometheus, então a carga aparece no mesmo dashboard do Grafana que as métricas do servidor.

    O que é testado

    flowchart LR
    k6([k6<br/>N usuários virtuais]) ==> lb[lb · Nginx] ==> gw["gateway<br/>(1, 2 ou 4 réplicas)"]
    gw <-->|token| redis[(Redis)]
    gw --> auth & account & exchange
    exchange -->|miss| api([AwesomeAPI])
    k6 -.->|remote write| prom[(Prometheus)] --> graf[Grafana]

    O setup() do script cria 20 contas e faz login uma vez; depois os usuários virtuais (VUs) reaproveitam os tokens, como usuários reais navegando logados. Cada VU espera 0,5–1,5 s entre as ações.

    Cenário Requisições O que exercita
    auth GET /auth/me + GET /accounts/{id} validação do token (Redis ou Auth), balanceamento, Account + PostgreSQL
    exchange GET /exchange/USD/BRL (80 %) e EUR/BRL gateway → Exchange → cache da cotação / API externa
    login POST /auth/login caminho caro: hash da senha + emissão do JWT
    mixed 80 % leitura autenticada, 15 % câmbio, 5 % login uso "real" da loja
    Perfil Forma da carga Pergunta que responde
    smoke 1 VU, 20 s O script e a plataforma funcionam?
    load sobe em 20 s até VUS, mantém por DURATION, desce Aguenta a carga esperada dentro do SLO?
    stress VUS → ×2 → ×4 → ×8, 30 s cada Onde quebra? Qual componente satura primeiro?
    spike VUS/10 → pico de VUS×4 em 5 s → volta Aguenta um pico repentino e se recupera?

    Critérios de aceitação (os mesmos do SLO), checados pelo k6 — ele sai com código 99 se algum estourar:

    Métrica Limite
    Erros (http_req_failed) < 1 %
    Latência p95 / p99 (respostas esperadas) < 500 ms / < 1500 ms
    checks (status e conteúdo das respostas) > 99 %

    Como rodar

    ./scripts/build.sh && docker compose up -d --build     # plataforma + Prometheus + Grafana

./scripts/load-test.sh                                  # mixed, perfil load, 50 VUs, 1 min
SCENARIO=auth PROFILE=stress VUS=50 ./scripts/load-test.sh
SCENARIO=exchange PROFILE=spike VUS=20 ./scripts/load-test.sh
THINK=0 SCENARIO=auth PROFILE=stress VUS=25 ./scripts/load-test.sh   # sem pausa: limite de vazão
BASE_URL=http://<endereço-do-elb> ./scripts/load-test.sh   # contra o EKS

./scripts/load-matrix.sh        # todos os experimentos abaixo (~25 min) -> load/results/RESULTS.md

    Enquanto roda, abra o Grafana em http://localhost:3000: a linha Teste de carga (k6) mostra VUs, req/s e p95/p99 do cliente, e as linhas de cima mostram o que acontece em cada réplica, no Redis e no Exchange no mesmo instante.

    Experimentos

    O scripts/load-matrix.sh muda uma variável por vez e mantém o resto igual (cache do Redis esvaziado antes de cada rodada):

    # Experimento Variável Cenário / perfil Hipótese
    1 Cache do token TOKEN_CACHE_ENABLED = false × true auth / load Sem cache, cada requisição chama o Auth: mais carga no Auth e latência maior quando ele satura. Com cache, gateway_token_cache_total{result="miss"} fica perto de 20 (um por usuário).
    2 Réplicas do gateway GATEWAY_REPLICAS = 1 × 2 × 4 auth / stress Mais réplicas atrasam o ponto em que o p95 estoura — até o gargalo passar para outro componente (Account/PostgreSQL ou a própria CPU da máquina).
    3 Cache da cotação EXCHANGE_CACHE_TTL = 0 × 30 exchange / load, 10 VUs, 30 s Sem cache, a latência do Exchange é a da API externa e aparecem 429; com cache, ~1 chamada externa a cada 30 s por réplica. Poucos VUs de propósito: não queremos martelar um serviço de terceiros.
    4 Uso real configuração padrão mixed / load Dentro do SLO.
    5 Saturação GATEWAY_REPLICAS = 1 × 4, THINK=0 (sem pausa) auth / stress até 200 VUs Com pausa, o experimento 2 não chega ao limite; sem pausa, cada VU dispara o mais rápido possível e mostra o que quebra primeiro.

    Resultados

    Medidos em 05/11/2026 com ./scripts/load-matrix.sh (os experimentos 3 e 5 foram rodados de novo com ONLY="3 5"). Máquina: Windows 11 + Docker Desktop (WSL2), 12 CPUs lógicas, 7,3 GiB de RAM para o Docker. k6, Nginx, gateway, serviços, banco, Prometheus e Grafana na mesma máquina. Latências só das respostas esperadas e só da fase de teste (o cadastro/login do setup() fica de fora).

    Todos os cenários com pausa (1–4) ficaram dentro do SLO (erros < 1 %, p95 < 500 ms, p99 < 1,5 s).

    O que os números mostram

    1. Cache do token (Redis) — o Auth sai do caminho. Com o cache ligado, o Prometheus registrou 7.571 hits e 21 misses em gateway_token_cache_total durante a rodada: 99,7 % das validações não chamaram o Auth (os 21 misses são ≈ 1 por usuário do teste). Sem cache, todas as ≈ 7.400 requisições passaram pelo POST /auth/solve. A latência caiu de p95 12 → 7 ms (−42 %). A vazão é a mesma nas duas rodadas porque quem dita o ritmo é a pausa dos usuários, não o servidor.

    2. Cache da cotação — a API externa sai do caminho. Sem cache, toda cotação ia até a AwesomeAPI: p50 de 23 ms e p95 de 49 ms, a latência de um serviço de terceiros. Com o cache de 30 s, p50 de 3 ms e p95 de 4 ms (−92 %). Em 10 usuários a API externa aguentou sem 429, mas o volume de chamadas a ela cai de ≈ 7 por segundo para 1 a cada 30 s por réplica — é isso que protege do limite de requisições.

    3. Réplicas com carga "realista" — um gateway sobra. Com a pausa entre ações, 400 usuários geram ≈ 290 req/s, e uma réplica só responde com p95 de 3 ms. As diferenças entre 1, 2 e 4 réplicas (3 / 17 / 7 ms) são ruído de JVMs recém-criadas (ainda sem o JIT aquecido), não ganho nem perda. Conclusão honesta: nessa carga o gateway não é o gargalo; o motivo para ter 2+ réplicas é disponibilidade (uma pode cair), não capacidade.

    4. Saturação — achamos o gargalo real, e não era o gateway. Sem pausa, a plataforma passou de 4.100 req/s com uma réplica do gateway, mas 0,57 % das requisições falharam (3.279), todas em GET /auth/me, nenhuma em GET /accounts/{id}. O gateway devolveu 500 e o log do Auth mostrou exatamente 3.279 × java.net.BindException: Cannot assign requested address:

    flowchart LR
    gw[gateway] -->|"GET /auth/me"| auth[Auth]
    auth -->|"Feign: 1 conexão TCP nova<br/>por chamada (sem pool)"| acc[Account]
    auth -.-x|"portas efêmeras<br/>esgotadas → 500"| acc

    O GET /auth/me do Auth chama o Account pelo OpenFeign com o cliente HTTP padrão, sem pool de conexões: cada requisição abre uma conexão TCP nova, e a 4.000 req/s as portas locais do container do Auth acabam (as fechadas ficam em TIME_WAIT). Com 4 réplicas do gateway a máquina ficou mais ocupada (CPU em ≈ 83 % nas duas rodadas, 4 JVMs disputando os mesmos núcleos), a vazão caiu para 2.697 req/s e o Auth não chegou no limite — por isso 0 erros, mas p95 o dobro.

    Correção sugerida (Auth — Nicolas)

    Trocar o cliente do Feign por um com pool de conexões e keep-alive — adicionar io.github.openfeign:feign-hc5 ao auth-service e spring.cloud.openfeign.httpclient.hc5.enabled=true. Com conexões reaproveitadas, o Auth deixa de abrir uma porta por requisição. Depois, repetir ONLY=5 ./scripts/load-matrix.sh para confirmar que os 500 somem.

    5. Uso real (mixed). Dentro do SLO, mas com a cauda mais longa da bateria (p95 62 ms, p99 197 ms): 5 % das ações são POST /auth/login, que faz o hash da senha (custoso de propósito) e emite o JWT.

    Limitações

    • Tudo na mesma máquina: o k6 disputa CPU com a plataforma. Os números mostram tendências e gargalos, não a capacidade do EKS. Em nós separados, mais réplicas devem aumentar a vazão — aqui ficaram presas à mesma CPU.
    • Rodadas curtas (1–3 min) e uma execução por configuração: diferenças de poucos ms são ruído.
    • 20 contas reutilizadas: favorece o cache do token (é o padrão de uso logado, mas um teste com milhares de usuários novos teria mais misses).

    Para medir a capacidade real: BASE_URL=http://<elb> ./scripts/load-test.sh a partir de outra máquina.

    Teste no EKS com HPA

    O curso pede um vídeo do teste de carga em execução com o HPA escalando. Roteiro para o dia do EKS: k6 rodando da máquina de um integrante contra o ELB, e o Horizontal Pod Autoscaler criando réplicas do gateway quando a CPU média passa de 50 % do request (250m → 125m por pod).

    Antes de começar

    • kubectl 1.36 ou mais novo (kubectl version --client): o cluster é 1.37 e o kubectl só tem suporte com até uma versão de diferença. O --cpu=50% do terminal 1 não existe antes do 1.34 (unknown flag: --cpu).
    • metrics-server instalado no cluster (o EKS não traz, e o eks-store.yaml não instala; sem ele o HPA fica em <unknown>). Instalar e conferir: kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml e, depois de ≈ 1 min, kubectl top nodes.
    • Cenário auth, não exchange nem mixed: a AwesomeAPI devolveu 429 para o IP da AWS, então o Exchange responde 503 no EKS (o mixed tem 15 % de câmbio: sairiam ≈ 15 % de erro).
    • Ninguém faz push na main durante a gravação: o deploy do CI faz kubectl apply do manifesto do gateway (replicas: 2) e briga com o HPA.
    • Capacidade: os 2 nós fixos têm espaço para mais ≈ 6 réplicas do gateway (conta em Custos), 8 no total. Com --max=10, as réplicas 9 e 10 ficariam Pending. O roteiro usa --max=6 para ter folga: a sobra está dividida entre os 2 nós (≈ 0,8 vCPU em cada) e um pod não usa pedaços de nós diferentes, então a 7ª e a 8ª podem não caber. Se o grupo preferir mostrar o limite, --max=10 e os Pending viram parte do resultado.
    • Mais de uma tomada: antes de repetir o teste, kubectl rollout restart deployment/auth deployment/account -n store. No ensaio, o Auth foi morto por falta de memória na segunda rodada pesada seguida (achado).

    Três terminais lado a lado (no Windows não existe watch; o -w do kubectl faz o mesmo):

    kubectl autoscale deployment gateway --cpu=50% --min=2 --max=6 -n store
kubectl get hpa gateway -n store -w
# --cpu=50% existe desde o kubectl 1.34, que descontinuou o --cpu-percent=50 (ainda aceito,
# com aviso); num kubectl 1.33 ou anterior, só o --cpu-percent=50 funciona

    kubectl get pods -n store -l app=gateway -o wide -w

    ELB=$(kubectl get svc lb -n store -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
# (opcional) métricas do k6 no Grafana do cluster: noutro terminal,
#   kubectl port-forward svc/prometheus 9090 -n store
#   (no Linux, com --address 0.0.0.0: senão o container do k6 não alcança o port-forward)
BASE_URL=http://$ELB PROMETHEUS_RW_URL=http://host.docker.internal:9090 \
  NAME=eks-hpa SCENARIO=auth PROFILE=load VUS=100 DURATION=4m THINK=0 ./scripts/load-test.sh

    --min=2 porque o manifesto do gateway já sobe 2 réplicas: com --min=1 o HPA derrubaria uma logo no começo do vídeo. O HPA olha a CPU a cada 15 s e o metrics-server tem até ≈ 1 min de atraso, por isso o platô tem 4 min. Depois do teste, o HPA espera 5 min sem carga antes de reduzir as réplicas: dá para continuar gravando e mostrar a volta para 2.

    Print do Grafana durante o teste (página de Observabilidade): kubectl port-forward svc/grafana 3000 -n store, dashboard Store — plataforma. O painel "Réplicas no ar ao longo do tempo (HPA)" mostra a subida e a volta para 2; "Requisições/s por réplica" e "CPU por réplica" mostram as réplicas novas entrando e dividindo a carga.

    Gravar sem depender de janela: o scripts/hpa-record.py (código) roda os três terminais acima, grava o vídeo e tira os prints do Grafana sozinho (detalhes no ensaio local):

    pip install playwright imageio-ffmpeg pillow    # uma vez; usa o Edge instalado
python scripts/hpa-record.py --base-url http://$ELB --name eks-hpa --label "EKS (eks-store)"

    O que esperar (visto no ensaio local): as réplicas novas levaram ≈ 1,5 min para receber a parte delas da carga (por quê); com o keepalive_time 10s aplicado depois no lb, devem levar ≈ 35–40 s. Na redução, os pods removidos aparecem como Error no terminal 2. Esse Error é o código de saída 143 (128 + SIGTERM) que a JVM devolve quando o Kubernetes manda o pod parar, conferido no state.terminated.exitCode do pod: não é falha.

    Depois: apagar o HPA (kubectl delete hpa gateway -n store) antes de apagar o cluster.

    Ensaio local (kind)

    O roteiro acima foi ensaiado em 12/11/2026, antes do dia do EKS, num cluster kind (Kubernetes dentro do Docker) montado para ficar parecido com o eks-store e com os mesmos manifestos:

    eks-store (EKS) Ensaio local (kind)
    Kubernetes 1.37 1.37
    Nós 2 × t3.medium 2 workers com o alocável de um t3.medium (1930m de CPU, 3,4 GiB)
    Manifestos k8s/ e o k8s/ de cada serviço os mesmos; muda só a imagem (a do docker compose build)
    Banco RDS Postgres dentro do cluster
    Entrada ELB → lb localhost:8081 → NodePort do lb
    HPA metrics-server metrics-server

    A conta de capacidade de Custos se confirmou: com a plataforma no ar, cada nó tinha 1050m de CPU reservados de 1930m, ou seja, cabem mais 3 gateways por nó (+6 no total). O ensaio não reproduz a latência do EKS (os nós do kind dividem os 12 núcleos da máquina, então um nó pode passar de 2 vCPU) nem o caminho pela internet e pelo ELB.

    docker compose build              # imagens dos serviços
./scripts/kind-up.sh              # cluster + plataforma (≈ 4 min)
python scripts/hpa-record.py      # HPA + k6 + vídeo + prints do Grafana (≈ 11 min)

    Achado: as réplicas novas demoram ≈ 1,5 min para receber carga

    O painel Requisições/s por réplica (as faixas empilhadas, uma por réplica) mostrou o que o k6 sozinho não mostra: as 4 réplicas que o HPA criou ficaram prontas em +64 s, mas receberam 0 req/s até ≈ +75 s e só dividiram a carga por igual em ≈ +150 s.

    Tempo desde o início do k6 2 réplicas antigas (req/s cada) 4 réplicas novas (req/s cada)
    +60 s ≈ 740 0
    +90 s ≈ 520 60 – 100
    +120 s ≈ 360 175 – 340
    +150 s ≈ 255 210 – 380

    A CPU mostra o outro lado: as 4 réplicas novas começam em 85–97 % de 1 CPU quase sem receber requisições (é a JVM aquecendo: carga de classes e compilação), enquanto as 2 antigas seguram a carga em ≈ 60–70 %. Só por volta de +140 s todas ficam em ≈ 30–40 %.

    Por quê: o lb (Nginx) fala com o Service gateway, que é um IP virtual, e reaproveita as conexões (keepalive 32 no upstream). O Service balanceia conexões, não requisições: cada conexão nova é sorteada entre os pods, mas uma conexão aberta fica no pod em que nasceu. As réplicas novas só recebem conexões novas e, com a carga estável, o Nginx só abre uma conexão nova quando fecha uma antiga, o que por padrão acontece depois de 1000 requisições na mesma conexão (keepalive_requests). Com ≈ 100 requisições em paralelo e ≈ 1.600 req/s, cada conexão faz ≈ 16 req/s e leva ≈ 1 min para chegar a 1000. No compose não acontece porque lá o Nginx enxerga cada réplica pelo DNS do Docker e divide as requisições ele mesmo.

    Correções possíveis (k8s/lb.yaml, Leonardo): a 1 foi aplicada depois do ensaio, então o teste no EKS já roda com ela.

    1. Uma linha no upstream gateways: keepalive_time 10s; (Nginx ≥ 1.21.3). Cada conexão dura no máximo 10 s, então as réplicas novas entram na divisão bem mais cedo. Testado no ensaio, em duas rodadas de 3 min: a carga ficou dividida por igual ≈ 35–40 s depois de as réplicas novas ficarem prontas, contra ≈ 86 s sem a linha, e a rodada com Auth e Account recém-reiniciados terminou com 0 erros. A vazão dessas rodadas não serve de comparação (numa o Auth caiu, como no achado abaixo; na outra Auth e Account tinham acabado de reiniciar).
    2. Igual ao compose: um Service headless (clusterIP: None) para o gateway e, no Nginx, server <service-headless>:8080 resolve; com resolver kube-dns.kube-system.svc.cluster.local valid=10s;. O Nginx passa a enxergar cada pod e divide as requisições ele mesmo, como no compose.

    Achado: o Auth foi morto por falta de memória na rodada seguinte

    Na rodada de comparação acima (a segunda rodada pesada seguida), o Auth foi OOMKilled (código 137) aos +3 min: nos ≈ 30–40 s seguintes, enquanto ele reiniciava, o gateway recebeu connection refused e connect timeout do Auth e devolveu 500 em 0,52 % das requisições (1.413 falhas, todas em GET /auth/me).

    A causa está no Dockerfile dos quatro serviços Java: -XX:MaxRAMPercentage=75. Com o limite de 512 Mi do Auth, o heap pode chegar a 384 Mi e sobram só 128 Mi para o resto da JVM (metaspace, threads, código compilado), pouco para um Spring Boot sob carga. A primeira rodada fez o heap crescer e a segunda passou do limite. O Account, com a mesma configuração, estava em 393 Mi de 512 Mi.

    • No dia do EKS: entre uma tomada e outra do vídeo, reiniciar o Auth e o Account (kubectl rollout restart deployment/auth deployment/account -n store).
    • Correção sugerida (Nicolas): -XX:MaxRAMPercentage=60 (heap até ≈ 307 Mi, ≈ 205 Mi para o resto) ou limite de 768 Mi no k8s.yaml do Auth e do Account. O request, que é o que o scheduler reserva, não muda, então a conta de capacidade de Custos continua valendo.

    // Teste de carga da plataforma (k6). Rodar com ./scripts/load-test.sh.
//
// Variáveis:
//   BASE_URL  http://lb (dentro da rede do compose) ou o endereço do ELB
//   SCENARIO  auth | exchange | login | mixed           (padrão: mixed)
//   PROFILE   smoke | load | stress | spike              (padrão: load)
//   VUS       usuários virtuais no platô                 (padrão: 50)
//   DURATION  duração do platô                           (padrão: 1m)
//   USERS     contas criadas no setup e reutilizadas     (padrão: 20)
//   NAME      nome do resultado em load/results/          (padrão: SCENARIO-PROFILE)
//   THINK     pausa entre ações, em s (padrão: 0.5-1.5 aleatório; 0 = sem pausa,
//             para achar o limite de vazão)
//
// Cenários:
//   auth      GET /auth/me + GET /accounts/{id}: rota protegida -> gateway valida o
//             token (Redis ou Auth) -> serviço. Mede cache do token e balanceamento.
//   exchange  GET /exchange/USD/BRL (e EUR/BRL): mede o cache da cotação.
//   login     POST /auth/login: caminho caro (hash da senha + emissão do JWT).
//   mixed     80% leitura autenticada, 15% câmbio, 5% login (uso "real" da loja).

import http from 'k6/http';
import { check, sleep } from 'k6';
import exec from 'k6/execution';
import { textSummary } from 'https://jslib.k6.io/k6-summary/0.1.0/index.js';

const BASE_URL = __ENV.BASE_URL || 'http://lb';
const SCENARIO = __ENV.SCENARIO || 'mixed';
const PROFILE = __ENV.PROFILE || 'load';
const VUS = parseInt(__ENV.VUS || '50', 10);
const DURATION = __ENV.DURATION || '1m';
const USERS = parseInt(__ENV.USERS || '20', 10);
const NAME = __ENV.NAME || `${SCENARIO}-${PROFILE}`;
const THINK = __ENV.THINK;
const PASSWORD = 'carga-senha-123';

const PROFILES = {
  // 1 usuário, só para ver se o script e a plataforma funcionam
  smoke: [
    { duration: '1s', target: 1 },
    { duration: '20s', target: 1 },
  ],
  // carga esperada: sobe, mantém o platô, desce
  load: [
    { duration: '20s', target: VUS },
    { duration: DURATION, target: VUS },
    { duration: '10s', target: 0 },
  ],
  // aumenta até achar o ponto de quebra (onde p95 ou erros estouram)
  stress: [
    { duration: '30s', target: VUS },
    { duration: '30s', target: VUS * 2 },
    { duration: '30s', target: VUS * 4 },
    { duration: '30s', target: VUS * 8 },
    { duration: '20s', target: 0 },
  ],
  // pico repentino (ex.: promoção): a plataforma se recupera?
  spike: [
    { duration: '10s', target: Math.max(1, Math.floor(VUS / 10)) },
    { duration: '5s', target: VUS * 4 },
    { duration: '30s', target: VUS * 4 },
    { duration: '5s', target: Math.max(1, Math.floor(VUS / 10)) },
    { duration: '30s', target: Math.max(1, Math.floor(VUS / 10)) },
    { duration: '5s', target: 0 },
  ],
};

export const options = {
  scenarios: {
    [SCENARIO]: {
      executor: 'ramping-vus',
      startVUs: 0,
      stages: PROFILES[PROFILE] || PROFILES.load,
      gracefulRampDown: '10s',
    },
  },

};

const JSON_HEADERS = { 'Content-Type': 'application/json' };

// tag "phase": separa o setup() (cadastro/login das contas) da carga medida
const tags = (name, phase = 'test') => ({ name, phase });

function login(email, phase = 'test') {
  const res = http.post(`${BASE_URL}/auth/login`, JSON.stringify({ email, password: PASSWORD }), {
    headers: JSON_HEADERS,
    tags: tags('POST /auth/login', phase),
  });
  const cookie = res.cookies.__store_jwt_token;
  return cookie && cookie.length ? cookie[0].value : null;
}

// Cria USERS contas e faz login uma vez: os VUs reutilizam os tokens, como
// usuários reais navegando logados (é isso que o cache do token aproveita).
export function setup() {
  const run = `${Date.now()}`;
  const users = [];
  for (let i = 0; i < USERS; i++) {
    const email = `carga+${run}-${i}@store.test`;
    const reg = http.post(
      `${BASE_URL}/auth/register`,
      JSON.stringify({ name: `Carga ${i}`, email, password: PASSWORD }),
      { headers: JSON_HEADERS, tags: tags('setup', 'setup') },
    );
    if (reg.status !== 200 && reg.status !== 201) {
      exec.test.abort(`POST /auth/register respondeu ${reg.status}: ${reg.body}`);
    }
    const token = login(email, 'setup');
    if (!token) exec.test.abort('login não devolveu o cookie __store_jwt_token');
    const me = http.get(`${BASE_URL}/auth/me`, {
      headers: { Cookie: `__store_jwt_token=${token}` },
      tags: tags('setup', 'setup'),
    });
    users.push({ email, token, id: me.json('id') });
  }
  return { users };
}

function authRead(user) {
  const params = { headers: { Cookie: `__store_jwt_token=${user.token}` } };
  const me = http.get(`${BASE_URL}/auth/me`, Object.assign({ tags: tags('GET /auth/me') }, params));
  check(me, { 'auth/me 200': (r) => r.status === 200 });
  const acc = http.get(`${BASE_URL}/accounts/${user.id}`, Object.assign({ tags: tags('GET /accounts/{id}') }, params));
  check(acc, { 'accounts/{id} 200': (r) => r.status === 200 });
}

function exchange(user) {
  const pair = Math.random() < 0.8 ? 'USD/BRL' : 'EUR/BRL';
  const res = http.get(`${BASE_URL}/exchange/${pair}`, {
    headers: { Cookie: `__store_jwt_token=${user.token}` },
    tags: tags('GET /exchange/{from}/{to}'),
  });
  check(res, {
    'exchange 200': (r) => r.status === 200,
    'exchange sell >= buy': (r) => r.status === 200 && r.json('sell') >= r.json('buy'),
  });
}

function doLogin(user) {
  check(login(user.email), { 'login devolve token': (t) => !!t });
}

export default function (data) {
  const user = data.users[(exec.vu.idInTest - 1) % data.users.length];
  switch (SCENARIO) {
    case 'auth':
      authRead(user);
      break;
    case 'exchange':
      exchange(user);
      break;
    case 'login':
      doLogin(user);
      break;
    default: {
      const r = Math.random();
      if (r < 0.8) authRead(user);
      else if (r < 0.95) exchange(user);
      else doLogin(user);
    }
  }
  // "tempo de leitura" do usuário: sem isso cada VU vira um loop sem pausa
  if (THINK === undefined) sleep(0.5 + Math.random());
  else if (parseFloat(THINK) > 0) sleep(parseFloat(THINK));
}

// Resumo no terminal + JSON completo + uma linha de tabela markdown, para o
// scripts/load-matrix.sh juntar os resultados em load/results/RESULTS.md.
export function handleSummary(data) {
  const m = data.metrics;
  // só a fase de teste (submétricas criadas pelos thresholds com {phase:test})
  const d = m['http_req_duration{phase:test,expected_response:true}'];
  const reqs = m['http_reqs{phase:test}'];
  const failed = m['http_req_failed{phase:test}'];
  const fmt = (v) => (v === undefined ? '-' : v.toFixed(0));
  const row =
    `| ${NAME} | ${SCENARIO} | ${PROFILE} | ${m.vus_max ? m.vus_max.values.max : '-'} ` +
    `| ${reqs.values.count} | ${reqs.values.rate.toFixed(1)} ` +
    `| ${fmt(d.values.med)} | ${fmt(d.values['p(95)'])} | ${fmt(d.values['p(99)'])} ` +
    `| ${(failed.values.rate * 100).toFixed(2)} % |\n`;
  return {
    stdout: textSummary(data, { indent: ' ', enableColors: true }),
    [`/results/${NAME}.json`]: JSON.stringify(data, null, 2),
    [`/results/${NAME}.row.md`]: row,
  };
}

def find_bash() -> str:

def wait_port(port: int, timeout: float = 30) -> None:
    end = time.time() + timeout
    while time.time() < end:
        with socket.socket() as s:
            s.settimeout(1)
            if s.connect_ex(("127.0.0.1", port)) == 0:
                return
        time.sleep(0.5)
    sys.exit(f"porta {port} não abriu (port-forward falhou?)")


def mmss(seconds: float) -> str:
    seconds = max(0, int(seconds))
    return f"{seconds // 60:02d}:{seconds % 60:02d}"


class Kube:
    def __init__(self, context: str | None, ns: str):
        self.base = ["kubectl"] + (["--context", context] if context else [])
        self.ns = ns

    def argv(self, *a: str) -> list[str]:
        return self.base + list(a) + ["-n", self.ns]

    def display(self, *a: str) -> str:
        return " ".join(self.argv(*a))

    def run(self, *a: str, check: bool = True) -> subprocess.CompletedProcess:
        return subprocess.run(self.argv(*a), capture_output=True, text=True,
                              encoding="utf-8", errors="replace", check=check)

    def json(self, *a: str):
        r = self.run(*a, "-o", "json", check=False)
        return json.loads(r.stdout) if r.returncode == 0 and r.stdout.strip() else None

    def cpu_flag(self, pct: int) -> str:
        """--cpu=50% existe desde o kubectl 1.34; antes dele, só --cpu-percent=50."""
        h = subprocess.run(self.base + ["autoscale", "--help"], capture_output=True, text=True,
                           encoding="utf-8", errors="replace").stdout
        return f"--cpu={pct}%" if "--cpu=" in h else f"--cpu-percent={pct}"

class State:
    def __init__(self, label: str, hpa_min: int, hpa_max: int, cpu: int):
        self.lock = threading.Lock()
        self.label, self.min, self.max, self.cpu_target = label, hpa_min, hpa_max, cpu
        self.t_rec = time.time()
        self.t_k6: float | None = None
        self.t_k6_end: float | None = None
        self.phase = "preparando"
        self.current = self.desired = self.cpu = None
        self.pods = self.ready = self.pending = self.terminating = 0
        self.timeline: list[dict] = []

    def snapshot(self) -> dict:
        with self.lock:
            now = time.time()
            return {
                "label": self.label, "phase": self.phase, "now": datetime.now().strftime("%H:%M:%S"),
                "rec": mmss(now - self.t_rec),
                "k6": mmss((self.t_k6_end or now) - self.t_k6) if self.t_k6 else None,
                "current": self.current, "desired": self.desired, "cpu": self.cpu,
                "cpu_target": self.cpu_target, "max": self.max,
                "pods": self.pods, "ready": self.ready, "pending": self.pending,
                "terminating": self.terminating,
            }


def poll_cluster(kube: Kube, st: State, stop: threading.Event) -> None:
    """A cada ≈ 3 s: réplicas do HPA, CPU média e estado dos pods do gateway."""
    while not stop.is_set():
        hpa = kube.json("get", "hpa", "gateway")
        pods = kube.json("get", "pods", "-l", "app=gateway")
        row = {"t": round(time.time(), 1)}
        with st.lock:
            if hpa:
                s = hpa.get("status", {})
                st.current, st.desired = s.get("currentReplicas"), s.get("desiredReplicas")
                cpu = None
                for m in s.get("currentMetrics") or []:
                    cpu = (m.get("resource") or {}).get("current", {}).get("averageUtilization")
                st.cpu = cpu
            if pods:
                items = pods.get("items", [])
                st.pods = len(items)
                st.terminating = sum(1 for p in items if p["metadata"].get("deletionTimestamp"))
                # sem espaço em nenhum nó (o "Pending" de quem só está criando o container não conta)
                st.pending = sum(1 for p in items if any(
                    c["type"] == "PodScheduled" and c["status"] == "False" for c in p["status"].get("conditions", [])))
                st.ready = sum(1 for p in items if not p["metadata"].get("deletionTimestamp") and any(
                    c["type"] == "Ready" and c["status"] == "True" for c in p["status"].get("conditions", [])))
            row.update(phase=st.phase, current=st.current, desired=st.desired, cpu=st.cpu,
                       pods=st.pods, ready=st.ready, pending=st.pending, terminating=st.terminating)
            st.timeline.append(row)
        stop.wait(3)

class Pane:
    def __init__(self, idx: int, title: str, logdir: Path):
        self.title = title
        self.path = logdir / f"terminal{idx + 1}.log"
        self.f = open(self.path, "wb", buffering=0)
        self.procs: list[subprocess.Popen] = []

    def run(self, argv: list[str], display: str, env: dict | None = None, wait: bool = False):
        self.f.write(f"$ {display}\n".encode())
        p = subprocess.Popen(argv, stdout=self.f, stderr=subprocess.STDOUT, stdin=subprocess.DEVNULL,
                             env=env, cwd=ROOT)
        self.procs.append(p)
        if wait:
            p.wait()
        return p

    def stop(self) -> None:
        for p in self.procs:
            if p.poll() is None:
                p.terminate()

def serve(panes: list[Pane], st: State, titles: list[str]) -> http.server.ThreadingHTTPServer:
    page = PAGE.replace("__TITLES__", json.dumps(titles)).replace("__TARGET__", str(st.cpu_target)).encode()

    class H(http.server.BaseHTTPRequestHandler):
        def log_message(self, *a):
            pass

        def send(self, body: bytes, ctype: str):
            self.send_response(200)
            self.send_header("Content-Type", ctype)
            self.send_header("Cache-Control", "no-store")
            self.end_headers()
            self.wfile.write(body)

        def do_GET(self):
            u = urllib.parse.urlparse(self.path)
            if u.path == "/":
                return self.send(page, "text/html; charset=utf-8")
            if u.path == "/status":
                return self.send(json.dumps(st.snapshot()).encode(), "application/json")
            if u.path.startswith("/log/"):
                i = int(u.path.rsplit("/", 1)[1])
                start = int(urllib.parse.parse_qs(u.query).get("from", ["0"])[0])
                with open(panes[i].path, "rb") as f:
                    f.seek(start)
                    data = f.read()
                cut = data.rfind(b"\n") + 1          # só linhas completas
                text = data[:cut].decode("utf-8", "replace").rstrip("\n")
                return self.send(json.dumps({"text": text, "next": start + cut}).encode(), "application/json")
            self.send_error(404)

    srv = http.server.ThreadingHTTPServer(("127.0.0.1", 0), H)
    threading.Thread(target=srv.serve_forever, daemon=True).start()
    return srv


def record(url: str, frames_dir: Path, fps: float, stop: threading.Event, out: list, browser: str) -> None:

def encode(frames: list, out_mp4: Path, speed: float = 1.0) -> None:
    import imageio_ffmpeg
    lst = out_mp4.with_suffix(".txt")
    with open(lst, "w", encoding="utf-8") as f:
        f.write("ffconcat version 1.0\n")
        for (path, t), nxt in zip(frames, frames[1:] + [None]):
            f.write(f"file '{path.as_posix()}'\n")
            f.write(f"duration {((nxt[1] - t) if nxt else 1.0):.3f}\n")
        f.write(f"file '{frames[-1][0].as_posix()}'\n")
    vf = (f"setpts=PTS/{speed}," if speed != 1 else "") + "fps=10,format=yuv420p"
    subprocess.run([imageio_ffmpeg.get_ffmpeg_exe(), "-y", "-loglevel", "error", "-f", "concat", "-safe", "0",
                    "-i", str(lst), "-vf", vf, "-c:v", "libx264", "-preset", "medium", "-tune", "stillimage",
                    "-crf", "24", "-movflags", "+faststart", str(out_mp4)], check=True)
    lst.unlink()

def wait_prometheus_replicas(port: int, n: int, timeout: float = 90) -> None:
    """O Prometheus leva ≈ 15-30 s para notar réplicas removidas: sem esperar, o começo dos gráficos
    mostraria as réplicas que sobraram de uma rodada anterior."""
    q = urllib.parse.urlencode({"query": 'sum(up{job="gateway"})'})
    end = time.time() + timeout
    while time.time() < end:
        try:
            res = json.load(urllib.request.urlopen(f"http://127.0.0.1:{port}/api/v1/query?{q}", timeout=5))
            v = res["data"]["result"]
            if v and round(float(v[0]["value"][1])) == n:
                return
        except Exception:
            pass
        time.sleep(2)
    print(f"   (o Prometheus ainda não vê {n} réplicas; seguindo assim mesmo)")

    ap.add_argument("--prom-port", type=int, default=9090)
    ap.add_argument("--grafana-port", type=int, default=3000)
    ap.add_argument("--browser", default="msedge", help="msedge | chrome | chromium")
    ap.add_argument("--keep-hpa", action="store_true", help="não apagar o HPA no fim")
    ap.add_argument("--keep-frames", action="store_true")
    ap.add_argument("--prints-only", action="store_true",
                    help="só refaz os prints do Grafana de uma gravação já feita (usa o resumo.json)")
    a = ap.parse_args()
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")  # console do Windows

    kube = Kube(a.context, a.namespace)
    out = ROOT / "load" / "results" / a.name
    if a.prints_only:
        t = json.loads((out / "resumo.json").read_text(encoding="utf-8"))["t"]
        with open(out / "port-forward.log", "ab") as log:
            pf = port_forward(kube, "grafana", a.grafana_port, 3000, log)
            try:
                all_prints(kube, a.grafana_port, t, out, a.browser)
            finally:
                pf.terminate()
        print(">> prints em", out)
        return
    frames_dir = out / "frames"
    if frames_dir.exists():
        shutil.rmtree(frames_dir)
    frames_dir.mkdir(parents=True)

    # 0. pré-requisitos e estado inicial: sem HPA, gateway com 2 réplicas
    if not kube.json("get", "deployment", "gateway"):
        sys.exit("deployment gateway não encontrado (contexto/namespace certos?)")
    print(">> zerando: sem HPA, gateway com", a.min, "réplicas")
    kube.run("delete", "hpa", "gateway", "--ignore-not-found")
    kube.run("scale", "deployment", "gateway", f"--replicas={a.min}")
    kube.run("rollout", "status", "deployment/gateway", "--timeout=300s")
    for _ in range(120):
        pods = kube.json("get", "pods", "-l", "app=gateway") or {"items": []}
        if len(pods["items"]) == a.min:
            break
        time.sleep(2)
    for _ in range(60):
        if kube.run("top", "pods", "-l", "app=gateway", check=False).returncode == 0:
            break
        print("   esperando o metrics-server...")
        time.sleep(5)

    # port-forwards: Prometheus (métricas do k6) e Grafana (prints)
    pf_log = open(out / "port-forward.log", "wb")
    pfs = [port_forward(kube, "prometheus", a.prom_port, 9090, pf_log),
           port_forward(kube, "grafana", a.grafana_port, 3000, pf_log)]
    wait_prometheus_replicas(a.prom_port, a.min)

    st = State(a.label, a.min, a.max, a.cpu)
    titles = ["1 · HPA do gateway", "2 · Pods do gateway", "3 · k6 (cenário " + a.scenario + ", " + a.vus + " VUs)"]
    panes = [Pane(i, t, out) for i, t in enumerate(titles)]
    srv = serve(panes, st, titles)
    url = f"http://127.0.0.1:{srv.server_address[1]}/"

    stop_poll, stop_rec = threading.Event(), threading.Event()
    frames: list = []
    threading.Thread(target=poll_cluster, args=(kube, st, stop_poll), daemon=True).start()
    rec = threading.Thread(target=record, args=(url, frames_dir, a.fps, stop_rec, frames, a.browser), daemon=True)
    rec.start()
    time.sleep(3)
    print(">> gravando:", url)

    # 1 e 2: HPA e pods
    hpa_args = ("autoscale", "deployment", "gateway", kube.cpu_flag(a.cpu), f"--min={a.min}", f"--max={a.max}")
    panes[0].run(kube.argv(*hpa_args), kube.display(*hpa_args), wait=True)
    panes[0].run(kube.argv("get", "hpa", "gateway", "-w"), kube.display("get", "hpa", "gateway", "-w"))
    pod_args = ("get", "pods", "-l", "app=gateway", "-o", "wide", "-w")
    panes[1].run(kube.argv(*pod_args), kube.display(*pod_args))
    for _ in range(40):                       # o HPA lê a primeira métrica (sai do <unknown>)
        if st.cpu is not None:
            break
        time.sleep(1.5)
    time.sleep(5)

    # 3: k6
    prom = f"http://host.docker.internal:{a.prom_port}"
    env_k6 = {"BASE_URL": a.base_url, "PROMETHEUS_RW_URL": prom, "NAME": a.name, "SCENARIO": a.scenario,
              "PROFILE": "load", "VUS": a.vus, "DURATION": a.duration, "THINK": "0"}
    shown = " ".join(f"{k}={v}" for k, v in env_k6.items()) + " ./scripts/load-test.sh"
    with st.lock:
        st.phase, st.t_k6 = "k6 rodando", time.time()
    print(">> k6:", shown)
    k6 = panes[2].run([find_bash(), "scripts/load-test.sh"], shown, env={**os.environ, **env_k6})
    k6.wait()
    with st.lock:
        st.t_k6_end = time.time()
        st.phase = "k6 terminou · o HPA espera 5 min sem carga para reduzir"
    print(f">> k6 terminou (código {k6.returncode}); esperando o HPA voltar a {a.min}")

    # depois do k6: grava a volta para o mínimo
    end = time.time() + a.cooldown
    stable_since = None
    while time.time() < end:
        with st.lock:
            back = st.current == a.min and st.pods == a.min and st.terminating == 0
        stable_since = (stable_since or time.time()) if back else None
        if stable_since and time.time() - stable_since > 12:
            break
        time.sleep(2)
    with st.lock:
        st.phase = "fim: de volta a " + str(st.current) + " réplicas"
    time.sleep(4)
    t_end = time.time()

    stop_rec.set()
    rec.join()
    stop_poll.set()
    for p in panes:
        p.stop()
    srv.shutdown()

    # vídeos
    print(f">> {len(frames)} quadros; gerando vídeos")
    encode(frames, out / "hpa-tempo-real.mp4")
    encode(frames, out / f"hpa-{int(a.fast)}x.mp4", a.fast)

    # linha do tempo (t relativo ao início do k6) e resumo
    t0 = st.t_k6
    with open(out / "linha-do-tempo.csv", "w", newline="", encoding="utf-8") as f:
        w = csv.DictWriter(f, fieldnames=["t_k6_s", "phase", "current", "desired", "cpu", "pods", "ready",
                                          "pending", "terminating"])
        w.writeheader()
        for r in st.timeline:
            w.writerow({"t_k6_s": round(r["t"] - t0, 1), **{k: r[k] for k in w.fieldnames if k in r}})
    tl = [r for r in st.timeline if r["t"] >= t0]
    first_up = next((r["t"] - t0 for r in tl if (r["desired"] or 0) > a.min), None)
    max_cur = max((r["current"] or 0) for r in tl) if tl else None
    t_max = next((r["t"] - t0 for r in tl if r["current"] == max_cur), None)
    max_ready = max((r["ready"] or 0) for r in tl) if tl else None
    t_ready = next((r["t"] - t0 for r in tl if r["ready"] == max_ready), None)
    after = [r for r in tl if r["t"] >= st.t_k6_end]
    back = next((r["t"] - st.t_k6_end for r in after if r["current"] == a.min and r["pods"] == a.min), None)
    row = ROOT / "load" / "results" / f"{a.name}.row.md"
    resumo = {
        "label": a.label, "inicio": datetime.fromtimestamp(t0).isoformat(timespec="seconds"),
        "hpa": {"min": a.min, "max": a.max, "cpu_alvo_pct": a.cpu},
        "k6": {"vus": a.vus, "duracao": a.duration, "cenario": a.scenario, "codigo_saida": k6.returncode,
               "linha": row.read_text(encoding="utf-8").strip() if row.exists() else None},
        "primeiro_aumento_s": round(first_up, 1) if first_up is not None else None,
        "replicas_max": max_cur, "replicas_max_em_s": round(t_max, 1) if t_max is not None else None,
        "prontas_max": max_ready, "prontas_max_em_s": round(t_ready, 1) if t_ready is not None else None,
        "cpu_max_pct": max((r["cpu"] or 0) for r in tl) if tl else None,
        "pending_max": max((r["pending"] or 0) for r in tl) if tl else None,
        "volta_ao_minimo_s_apos_k6": round(back, 1) if back is not None else None,
        "duracao_gravacao_s": round(t_end - st.t_rec, 1),
        "t": {"gravacao": st.t_rec, "k6": st.t_k6, "k6_fim": st.t_k6_end, "fim": t_end},
    }
    (out / "resumo.json").write_text(json.dumps(resumo, ensure_ascii=False, indent=2), encoding="utf-8")

    print(">> prints do Grafana")
    try:
        all_prints(kube, a.grafana_port, resumo["t"], out, a.browser)
    except Exception as e:  # o vídeo já está salvo: refazer com --prints-only
        print("   falhou:", e, "(refazer com --prints-only)")

    for p in pfs:
        p.terminate()
    if not a.keep_hpa:
        kube.run("delete", "hpa", "gateway", "--ignore-not-found", check=False)
    if not a.keep_frames:
        shutil.rmtree(frames_dir, ignore_errors=True)
    print(json.dumps(resumo, ensure_ascii=False, indent=2))
    print(">> arquivos em", out)


if __name__ == "__main__":
    main()
