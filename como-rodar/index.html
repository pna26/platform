    Como rodar

    Pré-requisitos

    • Git, Java 25 e Maven 3.9+
    • Docker com Docker Compose v2

    Localmente (Docker Compose)

    git clone --recurse-submodules https://github.com/pna26/platform.git
cd platform

./scripts/build.sh            # mvn install das interfaces + mvn package dos serviços + cria o .env
docker compose up -d --build  # sobe db, redis, account, auth, exchange, gateway (2 réplicas) e lb
./scripts/smoke-test.sh       # teste ponta a ponta

    A plataforma fica em http://localhost:8080. Só o lb (Nginx) publica porta; os demais serviços ficam na rede interna do compose. O Grafana (http://localhost:3000) e o Prometheus (:9090) ficam presos ao 127.0.0.1 — ver Observabilidade.

    compose.yaml
    # Plataforma completa rodando localmente.
#   ./scripts/build.sh            # compila os jars (interfaces + serviços)
#   docker compose up -d --build  # sobe tudo; entrada em http://localhost:8080
#
# Só o lb (Nginx) publica porta para fora: gateway, auth, account, exchange,
# redis e db ficam na rede interna do compose (camada confiável). Prometheus
# (9090) e Grafana (3000) ficam presos ao 127.0.0.1 da máquina.

name: store

services:

  db:
    image: postgres:17
    environment:
      POSTGRES_USER: ${DB_USER:-store}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-store}
      POSTGRES_DB: ${DB_NAME:-store}
    volumes:
      - db_data:/var/lib/postgresql/data
    healthcheck:
      test: [ "CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}" ]
      interval: 5s
      timeout: 3s
      retries: 20

  # Bottleneck: cache. Guarda token -> id da conta para o gateway não chamar
  # o Auth em toda requisição (ver api/gateway-service/.../TokenCache.java)
  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data
    healthcheck:
      test: [ "CMD", "redis-cli", "ping" ]
      interval: 5s
      timeout: 3s
      retries: 20

  account:
    build:
      context: ./api/account-service
      dockerfile: Dockerfile
    environment:
      DATABASE_HOST: db
      DATABASE_PORT: 5432
      DATABASE_DB: ${DB_NAME:-store}
      DATABASE_USERNAME: ${DB_USER:-store}
      DATABASE_PASSWORD: ${DB_PASSWORD:-store}
    deploy:
      replicas: 1
    depends_on:
      db:
        condition: service_healthy

  auth:
    build:
      context: ./api/auth-service
      dockerfile: Dockerfile
    environment:
      # segredo vem do .env (scripts/build.sh gera um aleatório); nunca no código
      JWT_SECRET_KEY: ${JWT_SECRET_KEY:?defina JWT_SECRET_KEY no .env (veja .env.example)}
      JWT_DURATION: ${JWT_DURATION:-86400000}
    deploy:
      replicas: 1
    depends_on:
      - account

  gateway:
    build:
      context: ./api/gateway-service
      dockerfile: Dockerfile
    environment:
      REDIS_HOST: redis
      REDIS_PORT: 6379
      # liga/desliga o cache do token (para comparar no teste de carga)
      TOKEN_CACHE_ENABLED: ${TOKEN_CACHE_ENABLED:-true}
      CORS_ALLOWED_ORIGINS: ${CORS_ALLOWED_ORIGINS:-http://localhost,http://localhost:3000,http://localhost:8080}
    # sem "ports": só é alcançável pelo lb
    deploy:
      replicas: ${GATEWAY_REPLICAS:-2}
    depends_on:
      redis:
        condition: service_healthy
      auth:
        condition: service_started
      account:
        condition: service_started

  # Bottleneck: balanceamento de carga (Nginx na frente das réplicas do gateway)
  lb:
    image: nginx:1.29-alpine
    ports:
      - "${LB_PORT:-8080}:80"
    volumes:
      - ./setup/nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - gateway

  # Exchange (Python/FastAPI). Cotação da AwesomeAPI com cache em memória
  # (bottleneck: ver docs/bottlenecks/exchange-cache.md)
  exchange:
    build:
      context: ./api/exchange-service
      dockerfile: Dockerfile
    environment:
      CACHE_TTL: ${EXCHANGE_CACHE_TTL:-30}
      EXCHANGE_API_TOKEN: ${EXCHANGE_API_TOKEN:-}
    deploy:
      replicas: ${EXCHANGE_REPLICAS:-1}

  # Bottleneck: observabilidade (docs/bottlenecks/observability.md).
  # Portas só no 127.0.0.1 do host: ferramentas de operação, não da loja.
  prometheus:
    image: prom/prometheus:v3.5.0
    command:
      - --config.file=/etc/prometheus/prometheus.yml
      - --storage.tsdb.retention.time=7d
      # o k6 (scripts/load-test.sh) envia as métricas do teste por remote write
      - --web.enable-remote-write-receiver
    volumes:
      - ./setup/prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - prometheus_data:/prometheus
    ports:
      - "127.0.0.1:${PROMETHEUS_PORT:-9090}:9090"
    depends_on:
      - gateway
      - exchange

  grafana:
    image: grafana/grafana:12.1.0
    environment:
      PROMETHEUS_URL: http://prometheus:9090
      GF_SECURITY_ADMIN_PASSWORD: ${GRAFANA_ADMIN_PASSWORD:-admin}
      GF_AUTH_ANONYMOUS_ENABLED: "false"
      GF_DASHBOARDS_DEFAULT_HOME_DASHBOARD_PATH: /var/lib/grafana/dashboards/store.json
      GF_ANALYTICS_REPORTING_ENABLED: "false"
    volumes:
      - ./setup/grafana/provisioning:/etc/grafana/provisioning:ro
      - ./setup/grafana/dashboards:/var/lib/grafana/dashboards:ro
      - grafana_data:/var/lib/grafana
    ports:
      - "127.0.0.1:${GRAFANA_PORT:-3000}:3000"
    depends_on:
      - prometheus

volumes:
  db_data:
  redis_data:
  prometheus_data:
  grafana_data:

    O .env é criado pelo scripts/build.sh a partir do .env.example, com um JWT_SECRET_KEY aleatório (openssl rand -base64 32). Ele nunca vai para o git.

    Exemplo de uso

    # cadastro e login (o cookie fica no arquivo cookies.txt)
curl -X POST localhost:8080/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Ana","email":"ana@store.com","password":"123456"}'
curl -c cookies.txt -X POST localhost:8080/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"ana@store.com","password":"123456"}'

# rotas protegidas (o curl só reenvia cookie Secure em HTTPS, então mandamos o header)
TOKEN=$(awk '/__store_jwt_token/ {print $7}' cookies.txt)
curl -H "Cookie: __store_jwt_token=$TOKEN" localhost:8080/auth/me
curl -H "Cookie: __store_jwt_token=$TOKEN" localhost:8080/accounts

    Smoke test

    O scripts/smoke-test.sh é o mesmo que roda no CI (workflow integration). Ele confere:

    • cadastro, login (cookie HttpOnly), /auth/me, /accounts, /exchange/USD/BRL e logout;
    • 401 sem token, com token inválido e com id-account forjado;
    • que pelo menos 2 réplicas do gateway responderam (balanceamento);
    • que o token ficou em cache no Redis;
    • que /gateway/actuator/prometheus não fica exposto pelo lb.
    scripts/smoke-test.sh
    #!/usr/bin/env bash
# Teste ponta a ponta da plataforma rodando (compose local ou EKS):
#   ./scripts/smoke-test.sh                       # http://localhost:8080
#   BASE_URL=http://<elb-da-aws> ./scripts/smoke-test.sh
# Confere o contrato da API, o 401 sem token, o header id-account forjado,
# o balanceamento entre réplicas e o cache do token no Redis.
set -euo pipefail

BASE_URL="${BASE_URL:-http://localhost:8080}"
EMAIL="smoke+$(date +%s)$RANDOM@store.test"
PASS="senha-forte-123"
fail() { echo "FALHOU: $*" >&2; exit 1; }
ok() { echo "ok  - $*"; }
status() { curl -s -o /dev/null -w '%{http_code}' "$@"; }

echo ">> esperando o gateway em $BASE_URL"
for i in $(seq 1 60); do
  [ "$(status "$BASE_URL/health-check")" = "200" ] && break
  sleep 2
  [ "$i" = 60 ] && fail "gateway não respondeu"
done
ok "gateway no ar"

# o auth/account podem demorar um pouco mais que o gateway para subir
for i in $(seq 1 60); do
  code=$(status -X POST "$BASE_URL/auth/register" -H 'Content-Type: application/json' \
    -d "{\"name\":\"Smoke Test\",\"email\":\"$EMAIL\",\"password\":\"$PASS\"}")
  case "$code" in 200|201) break ;; esac
  sleep 3
  [ "$i" = 60 ] && fail "POST /auth/register respondeu $code"
done
ok "POST /auth/register ($code)"

headers=$(curl -s -D - -o /dev/null -X POST "$BASE_URL/auth/login" -H 'Content-Type: application/json' \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASS\"}")
echo "$headers" | head -1 | grep -q ' 200' || fail "POST /auth/login: $(echo "$headers" | head -1)"
TOKEN=$(echo "$headers" | tr -d '\r' | sed -n 's/^[Ss]et-[Cc]ookie: __store_jwt_token=\([^;]*\).*/\1/p' | head -1)
[ -n "$TOKEN" ] || fail "login não devolveu o cookie __store_jwt_token"
echo "$headers" | grep -qi 'set-cookie:.*HttpOnly' || fail "cookie sem HttpOnly"
ok "POST /auth/login devolveu o cookie __store_jwt_token (HttpOnly)"

COOKIE="Cookie: __store_jwt_token=$TOKEN"

[ "$(status "$BASE_URL/accounts")" = "401" ] || fail "GET /accounts sem token deveria ser 401"
ok "GET /accounts sem token -> 401"

[ "$(status -H 'id-account: forjado' "$BASE_URL/accounts")" = "401" ] || fail "id-account forjado abriu a rota"
ok "header id-account forjado sem token -> 401"

[ "$(status -H "Cookie: __store_jwt_token=token.invalido.x" "$BASE_URL/accounts")" = "401" ] || fail "token inválido deveria ser 401"
ok "token inválido -> 401"

me=$(curl -s -H "$COOKIE" "$BASE_URL/auth/me")
echo "$me" | grep -q "$EMAIL" || fail "GET /auth/me: $me"
ok "GET /auth/me devolve a conta logada"

ID=$(echo "$me" | sed -n 's/.*"id":"\([^"]*\)".*/\1/p')
[ "$(status -H "$COOKIE" "$BASE_URL/accounts")" = "200" ] || fail "GET /accounts com token"
ok "GET /accounts com token -> 200"
[ "$(status -H "$COOKIE" "$BASE_URL/accounts/$ID")" = "200" ] || fail "GET /accounts/{id}"
ok "GET /accounts/{id} -> 200"

[ "$(status "$BASE_URL/exchange/USD/BRL")" = "401" ] || fail "GET /exchange sem token deveria ser 401"
ok "GET /exchange/USD/BRL sem token -> 401"

# o exchange depende de uma API externa: 503 (fora do ar/limite) vira só aviso
ex=$(curl -s -w '\n%{http_code}' -H "$COOKIE" "$BASE_URL/exchange/USD/BRL")
code=$(echo "$ex" | tail -1); body=$(echo "$ex" | sed '$d')
case "$code" in
  200)
    echo "$body" | grep -q '"sell"' && echo "$body" | grep -q '"buy"' || fail "GET /exchange/USD/BRL: $body"
    echo "$body" | grep -q "\"id-account\":\"$ID\"" || fail "exchange não recebeu o id-account do gateway: $body"
    ok "GET /exchange/USD/BRL -> 200 com sell/buy e o id-account do usuário" ;;
  503) echo "aviso - exchange respondeu 503 (API de câmbio externa indisponível)" ;;
  *) fail "GET /exchange/USD/BRL respondeu $code: $body" ;;
esac
[ "$(status -H "$COOKIE" "$BASE_URL/exchanges/USD/XX")" = "400" ] || fail "/exchanges/{from}/{to} (apelido) deveria chegar no exchange"
ok "GET /exchanges/... (apelido) chega no exchange"

hosts=$(for i in $(seq 1 12); do curl -s "$BASE_URL/health-check"; echo; done | sort -u | wc -l | tr -d ' ')
if [ "$hosts" -ge 2 ]; then ok "balanceamento: $hosts réplicas diferentes do gateway responderam"
else echo "aviso - só 1 réplica do gateway respondeu (GATEWAY_REPLICAS=1?)"; fi

if command -v docker >/dev/null && docker compose ps redis >/dev/null 2>&1; then
  keys=$(docker compose exec -T redis redis-cli --scan --pattern 'gateway:token:*' | wc -l | tr -d ' ')
  [ "$keys" -ge 1 ] || fail "nenhum token em cache no redis"
  ok "cache: $keys token(s) em cache no Redis (chave = SHA-256 do JWT)"
fi

[ "$(status "$BASE_URL/gateway/actuator/prometheus")" = "404" ] || fail "métricas não deveriam ser públicas"
ok "/gateway/actuator/prometheus bloqueado no lb"

logout=$(curl -s -D - -o /dev/null "$BASE_URL/auth/logout")
echo "$logout" | grep -qi 'set-cookie: __store_jwt_token=;' || fail "logout não limpou o cookie"
ok "GET /auth/logout limpa o cookie"

echo ">> smoke test passou"

    Variações úteis

    docker compose up -d --scale gateway=4      # mais réplicas (o Nginx descobre sozinho)
TOKEN_CACHE_ENABLED=false docker compose up -d gateway   # desliga o cache (comparar no teste de carga)
docker compose up -d --scale exchange=3                  # mais réplicas do exchange
docker compose down -v                                    # derruba tudo e apaga os volumes

    No EKS

    O deploy no EKS é feito pelo pipeline (CI/CD): cada serviço aplica o seu k8s/ e o repositório platform aplica a infra compartilhada (k8s/lb.yaml e k8s/redis.yaml). Para aplicar manualmente:

    aws eks update-kubeconfig --name <cluster> --region <região>
kubectl create namespace store
kubectl apply -n store -f k8s/                         # lb (Nginx + LoadBalancer) e redis
kubectl apply -n store -f api/gateway-service/k8s/     # gateway
kubectl get svc lb -n store                            # endereço público do ELB
BASE_URL=http://<endereço-do-elb> ./scripts/smoke-test.sh
