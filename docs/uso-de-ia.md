# Use of AI

The assignment allows **partial** use of AI in the implementation, as long as it is documented: what was done
with AI help, what was done by the group, and everyone must be able to explain and defend any part
(including the AI-generated ones). This page is that record — each member fills in their own part.

!!! danger "Group rule"

    Nothing generated by AI goes in unless the owner has read, run and understood it. Before the
    presentation we do an internal walkthrough in which each member explains the others' parts.

**Where the AI got it wrong and it was fixed:**

- **OIDC rejected in the first CI run** (`Not authorized to perform sts:AssumeRoleWithWebIdentity`): the trust
  policy expected `repo:pna26/*`, but the repositories use GitHub's immutable *subject*
  (`repo:pna26@<id>/...`). Fixed and documented in [AWS](devops/aws.md).
- **ECR names:** the first repositories (`gateway`, `auth`...) did not match the names the pipeline
  uses (`*-service`). They were recreated with the right names and the old, empty ones deleted.
- **`docker login` to ECR failed on Windows:** the token exceeds the size the Credential Manager
  accepts. Solved with `docker-credential-ecr-login`.
- **CI permissions on the cluster:** `AmazonEKSEditPolicy` did not allow creating Prometheus's `Role`, and not even
  `AmazonEKSAdminPolicy` solved it, because Kubernetes' privilege-escalation check does not
  see the AWS policy. The fix was a `RoleBinding` to the `admin` role, only in the `store` namespace.
- **Fallback JWT key** in Auth's `application.yaml`: removed during the security review, and now Auth does not
  start without `JWT_SECRET_KEY`.
- It used `saveAndFlush`, which does not exist in account's `CrudRepository`: the build caught it and it became `save` (the
  transaction still guarantees that the account and the event are saved together).
- The messaging script failed in Git Bash on Windows: `/opt/kafka/...` became
  `C:/Program Files/Git/opt/...`. Fixed with `MSYS_NO_PATHCONV=1`.
- `smoke-test.sh` expected any user to be able to `GET /accounts` (200); with RBAC it became
  403, and the script got the new checks. The first `JwtService` test did not compile (invalid
  escape in a regular expression), and the build caught it before the commit.

**Where the AI got it wrong and it was fixed:**

- **k6 `smoke` profile did not run any iteration:** it ramped from 0 to 1 user within its own 20 s.
  Noticed on the first run; it became 1 fixed user.
- **The 60 requests from `setup()` were included in the statistics** (sign-up/login of the test accounts),
  skewing short runs. Fixed with the `phase=setup|test` tag.
- **The replicas experiment did not find a breaking point:** with the pause between actions, 400 users generate
  only ≈ 290 req/s. The saturation experiment (`THINK=0`) was created, and it found the real bottleneck in Auth.
- **The AI edited `load-matrix.sh` while it was running:** bash reads the script incrementally and started
  executing the wrong parts, corrupting the `exchange-cache-off` run. Experiment 3 was run again.
- Caught before the commit: `head -n -1` (does not work on the group's macOS), 2 `uvicorn` workers (each
  Prometheus scrape would see a different process) and the wrong `lb` `requests` in the cost calculation.
- **The EKS extended support alert was missing** (US$ 0.60/h): it came up while checking the prices.
